What it does

One binary for every repository on your machine

Each card opens its section on the features page.

Organised layout

Clones land in Public/, Private/ and Forks/, then by language, so the same repository is always at the same path. On macOS each folder also gets Finder tags.

How the layout works

Smart syncing

A sidecar file records each clone's last known push. When the forge reports nothing new, corralctl skips the git pull entirely.

How smart syncing works

Exec mode

Run one shell command across every clone at once, narrowed by language or visibility: git status, a test run, an audit.

How exec works

Mirror to other forges

corralctl sync pushes the organised tree out to GitLab, Gitea, Forgejo, Codeberg, Bitbucket or GitHub, and never force-pushes a branch.

How mirroring works

MCP server

Serves your local clones to AI coding agents. Read-only by default: no network calls, and the GitHub API is never contacted.

How the MCP server works

Cross-repository symbol lookup

Find where a function or type is declared, and where text is written, across every clone on the machine rather than the one an editor has open.

How symbol lookup works

Four ways people use corralctl

Developers

You own hundreds of repositories

AI agents

Security

Built to refuse before it deletes

corralctl runs with your own credentials on your own machine, so its security model is about limiting the blast radius of a mistake.

Prune and the MCP delete tool decline any clone holding uncommitted, unpushed, stashed, submodule or gitignored work. Tokens never reach a command line or .git/config, and every release is signed and reproducible.
